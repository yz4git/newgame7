# KAWAII MOTION — 実写風・ファン獲得ダンスバトル

iPhone縦画面専用の **動画分岐型ダンスパフォーマンスゲーム**。
プレイヤー「桜華」は、ライバル「レイナ」と観客ファンの支持を競います。

ゲームを遊ぶ: **https://yz4git.github.io/newgame7/**

## ルール
1. **STAGE START** でライブ開始。全5ビート。
2. 観客のリクエスト（♡かわいい／✦クール／★サプライズ）と、レイナの演出を観察。
3. 「APPEAL NOW」の時間帯に、下の3つから次のダンス演出を選択。
4. 選択しても動画は止まらず、準備した編集点で自然に次の映像へ。
5. 観客の好みと一致すると多くのファンを獲得し、ライバルから一部を奪える。
6. 同じタイプのアピールを連打すると飽きられる。ジャンルを変えて魅せるとチェーンボーナス。
7. 5つの演目を選んだあと、最後のダンスと結果演出へ。ファン数で勝敗を判定。

早すぎる入力は減点せず、予兆を見るよう案内します。判断を逃した場合はファン獲得なしでライバルが支持を増やし、次のカットで立て直せます。
**RETAKE** は2回まで。結果から戻って選び直すこともできます。**PERFORMANCE REPLAY** は選択した動画の流れを同じ順番・成績で再生します。

## ゲーム内映像について
現在のv1は**ゲームシステムの操作可能なアニマティック試作版**です。
CSSで動く桜華・レイナの簡易ダンスを表示しています。実写・高品質GIF/MP4は**まだ同梱していません**。

タイトルの「GIF・動画を割り当てる」、ゲーム内の「CLIPS」で、各シーンにiPhone内のMP4/GIF/WebM/WebPを一時割当できます。出発したシーン・選んだ演出に応じて専用の映像を使い分けることもできます。ファイルは外部サーバーにアップロードせず、このタブ内で利用します。ページを再読み込みすると一時割当は消えます。

### GitHubに動画を追加する
`assets/clips/` に映像を置き、`assets/manifest.json` で指定します。

```json
{
  "heart": {
    "default": "assets/clips/heart.mp4",
    "from": {
      "opening:heart": "assets/clips/heart_after_opening.mp4"
    }
  },
  "win": "assets/clips/encore.mp4"
}
```

映像の動作と音は元クリップ側に制作し、各ノードの再生時間とカットマーカーは `dance-graph.js` で管理します。
H.264 MP4、ポートレートの安全領域、明確な開始/終了姿勢を推奨します。
長時間素材や未確認GIFを大量に入れるとiPhoneのメモリ・転送量の負担になるため段階的に導入します。

## ファイル構成
- `index.html` — 縦型舞台・ファン数・選択UI・リプレイとクリップ管理。
- `dance.css` — 演出、ステージ、簡易ダンサーアニメーション、セーフエリア対応。
- `dance-graph.js` — 動作ノード、観客の好み、ライバルの演出、選択の次ノード。
- `dance.js` — ゲームロジック、ファン配点、入力・リテイク・結果・リプレイ。
- `assets/manifest.json` — MP4/GIFの割当。
- [新ゲーム仕様書](docs/KAWAII_MOTION_SPEC.md)。
- `tests/dance.test.cjs` — Node上での分岐・配点・リプレイ等の検証。

## 動画・絵コンテ制作方針
桜華とレイナを成人女性のダンスパフォーマーとして制作します。外見の一貫性、自然な身体の動き、カメラ、衣装、照明を固定してから動画を量産します。**戦闘・負傷・攻撃映像の制作は行いません。**

最初の実写テストルートは`opening → heart → step → finale → heart → step`。表情、ハートポーズ、フットワーク、舞台照明の切り替えが自然に接続できるか確認します。

## 技術・公開
依存CDNなしの静的サイト。GitHub Pages（`main`からActions自動公開）。iPhone Safari / PWA縦画面。画面内の複数指タップ、拡大誤動作を抑える設計。動画切り替えや連続プレイの実機検証は今後の作業です。
