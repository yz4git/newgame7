# GIF FIGHTERS: MOTION CHAIN — 仕様書 v0.1

更新: 2026-11-05 / 対象: iPhone Safari 縦画面 / repo: yz4git/newgame7

## 製品の核
動画を格闘ゲームの「見た目」ではなく「操作対象」にする。プレイヤーは映像クリップの再生中に次の展開（追撃・回避・カウンター・場面転換）を決断し、アクション映画のような一連の殺陣を作る。移動スティック・P/K/Gの通常格闘ゲームとは別物にする。

## MVPの遊び
- タイトル→START→短い映像クリップ→選択ウィンドウ→分岐→結末→結果・リプレイ。
- 画面上部は映画的な縦長の映像、下部は親指で押せる大きな分岐ボタン（2〜3択）。
- 選択肢は安全性／リスク／報酬を差別化。敵の予兆とタイミングで成功が変わる。
- チェーン/スコア/体力/リテイク回数を持つ。ミスはダメージやチェーン切断につながる。
- 「リテイク」は直前の分岐に戻って別ルートを選べる有限資源。
- 終了後に選択した映像パスを再生し、結果を確認できる。
- 実写素材がない場合でも、動作分岐の実装を検証できる代替アニマティックを表示する。完成版を装わない。

## 分岐データ
ノードには id, title, duration, cue / window, choices[], defaultChoice, actors, choreography, clipSrc, scene, intensity を持つ。各 choice は label, timing, risk, score, health, destination を持つ。繰り返し操作を受け付けず、1回の決定だけで遷移する。画像／GIF／MP4を動画レイヤーにマッピング可能にする。

## 再生エンジン
- 進行は requestAnimationFrame + 経過時刻で判定し、表示更新とは独立。
- HTMLVideoElement: muted, playsInline, preload=metadata; 再生拒否・ファイル未読込は代替映像へフォールバック。
- GIF画像はプレビュー用途（任意時刻へのシーク不可）、動画MP4/WebMは同期用途。
- クリップは枝の末端を含め個別に定義し、接続点に姿勢／画角の互換性を設ける（本編素材製作時）。
- 実写クリップのマテリアルは配信サイズ節約のため低ビットレートMP4/H.264を優先し、iPhone実機で検証。
- 現段階では動画の滑らかな編集接続は保証しない。予備データで分岐ロジックを先に完成させる。

## UI/UX
- iPhone縦固定を想定。safe-area、viewport-fit=cover、9:19.5中心。
- ゲーム面にtouch-action:none、操作面はPointerEvent。ズーム／画面選択／ダブルタップ誤操作回避。
- 左右の明確なタップ面積、残り時間と推奨タイミングを視覚表示。
- リプレイ、一時停止、音量切替、初期画面へ戻る。
- モーション低減設定と音量なしでも理解できる情報表示。

## 品質と範囲
- 目標60HzのUI描画（実動画fpsとは区別）。
- 不正な分岐、画面外タップ、連打、レース状態を排除。
- Phase 1は静的GitHub Pages（ビルド不要）、オフライン必須ではない。
- フォント・素材への外部CDN依存は原則使わない。

## MVP受け入れ条件
- 1本以上のクリアルートと失敗ルートがある。
- 3択を連続選択でき、ノード・スコアが画面に反映される。
- 選択の早すぎ・適正・遅すぎと無入力で結果が変わる。
- リテイクで同じ分岐をやり直せる。
- リプレイは実際に選んだ選択履歴を再現し、適切に終了する。
- GIF/MP4を任意ノードに後から割り当てられる構造がある。
- iPhone縦表示でUIがセーフエリアからはみ出さない。

## 制作素材契約
assets/clips/<node-id>.mp4 (H.264, 720x1280推奨) / GIFは短いループに限定。
出入りの姿勢・カメラの整合を確認し、シームが目立つ場合は演出カットで隠す。
ゲーム実装とフォトリアル素材の制作・導入を別のマイルストーンにする。

## 改訂方針 v0.2 — SHOT 01〜03 (2026-11-05)

レビュー結果を受け、[改訂縦画面絵コンテ v2](STORYBOARD_VERTICAL_V2.md)をこの3ショットの制作基準とする。

- LIVE CUTの動画スクラブ／繰り返し停止を採用しない。
- 暫定MOTION BRANCH: 相手の予兆に合わせて技の方向を選ぶ。判断窓の選択は保持し、演出上の接続マーカーで次ショットへ移る。選択時に動画を突然切らない。
- 早すぎる入力は失敗にしない（予兆を観察するよう促す）。判断窓内で決めればGOOD/PERFECT評価。最終的に何も選ばなければ失敗。
- 2026-11-05のv0.2改訂では最初の3ノードのみ適用。v0.3で残り7つの選択ノードにも同方式を適用済み。
- 重要: 固定接続時刻だけでは前後の動作の一致を保証しない。実写映像の入口差分・遮蔽カットは制作工程で検証する。
- リプレイは選択時刻と実分岐時刻を区別して扱う。
