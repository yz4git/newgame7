## 0. 作品全体の説明（映像制作チーム共有用）

仮タイトル: **MOTION CHAIN — 桜の残像 / ACT 01「交差する拳」**

夜の桜の屋上。中国武術を使う女性格闘家「桜華（Ouka）」と、実戦的なキックボクシングで戦う女性格闘家「レイナ（REINA）」が対峙する。レイナが先に間合いを詰める。次に何が起こるかはプレイヤーが決める。大胆に踏み込めば近距離の連撃へ、かわして見切れば鮮烈なカウンターへ、誘えば駆け引きのシーンへ分岐する。異なる分岐が途中で合流し、最後は強烈な一撃、静かな残心、または敗北の暗転で閉じる。

**この作品における場所の変化は「同じ現実空間を瞬間移動すること」ではなく、「プレイヤーが編集している格闘映画のシーン転換」である。** 例: 拳がレンズを隠す瞬間に桜の屋上から雨の路地へマッチカット、振り回した髪の軌跡にネオンの光が重なって次の撮影セットへ移る。転換はアクションの勢いに従う。見当違いの背景だけが突然現れることは禁止。

人物の性格: 桜華は華麗だが無駄のない動き。レイナは速く、重く、攻撃的。両者とも成人、互いの強さを認め合うライバル。過度な流血・損壊は描かない。目指すのは**痛みの残酷さより、殺陣と映画編集の快感**。

## 1. 画づくりの絶対ルール

- **画面:** iPhoneの全体画面は縦型。ゲーム内の映像窓は全画面の一部なので、動画マスターの基準は **3:4（1080×1440）** を推奨。ゲーム内の表示領域は実機で再測定する。別案の9:16素材は中央セーフ領域にアクションを収め、クロップを確認する。
- **画質:** 写真のような自然な皮膚・髪・衣装の質感。静止ポーズのスライドショーではなく、明確な重心移動を伴う連続アクション。モーションブラーは接触／切り返しの瞬間だけ。
- **fps:** 編集・素材生成の作業マスターは30fps基準（必要なスローモーション部分だけ60fps収録・生成を検討）。ゲームのUI更新60Hzと動画60fpsは別概念。
- **人物サイズ:** 交戦中は腰から上、または膝上までの中景を主軸とする。大技は全身ロング、決めは表情の寄りを織り交ぜる。蹴りの軌道や両者の位置関係が分かるよう、寄りの直後に引き画を入れる。
- **画面方向:** 原則「桜華＝画面左／レイナ＝右」。拳・蹴りの主進行方向は左→右。180度線を越える場合は明確な円弧カメラ移動または挿入カットを入れる。
- **衣装固定:** 桜華は深紅×金刺繍の中国武術風衣装、黒いインナーパンツ、低い武術靴、桜飾りと赤い髪紐。レイナは紺・黒・銀の動きやすい戦闘服、短いグローブと武術靴。衣装の細部は全クリップで固定。
- **環境:** 桜屋上 SAKURA、雨路地 RAIN、ネオン街 NEON、朱色の寺院 TEMPLEの4ルック。4つは「映画内のロケーション」で、各ルックの進入には映画的なカットを設ける。
- **画面下側:** iPhoneの操作ボタンがあるため、映像の下端ギリギリで技の意味を示さない。攻撃予兆を見せる手、肩、顔、腰の動作は映像中央の安全領域に置く。
- **音:** 会話は原則なし。衣擦れ・足音・呼気・拳の風切り・衝撃・環境音・音楽の拍で映像をつなぐ。サイレントでも敵の予兆が分かる演技を必須とする。
- **接続:** 分岐時は映像をそのまま切り替える。前後の身体姿勢が合わない場合は、拳が画面を覆う、素早いパン、前景の柱、逆光フラッシュなどで1〜数フレームの隠しカットを使う。**単純な黒フェードの連発は禁止**。

## 2. ひとつのクリップの基本構造

各ノードは「①入口（0〜25%） → ②予兆・対立（25〜40%） → ③判断可能なアクション（40〜80%） → ④未入力時の失敗へ接続（80〜100%）」で構成。タイミングは実装側の `duration` と `window` に連動。

**重要:** 入力の瞬間に次ノードへ飛ぶため、映像のどの時点で切られても「動作途中の自然な映画編集」に見えることが必須。映像が終わってから次を選ぶ普通の選択式ムービーにはしない。開始0.3〜0.5秒には接続先から受け取る姿勢を置く。

各シーンの下記時刻は `graph.js` 現行版に整合した **制作初期値**。実写化時に視認性が不足する場合は動画だけ延ばさず、データ側のduration・判断窓を一緒に改訂する。

- **結末:** `defeat`。リテイク余地があればUIで選べる。

## 4. 分岐一覧（30本／現行graph.jsと対応）

**入力の直後、次のノードのどの身体動作で受けるか**を定義する。単にIDをつなぐだけでは映像がジャンプするため、下記を各クリップの絵コンテ制作時の接続条件にする。

| 出発 | 選択 → 行先 | 映像の接続指示 |
|---|---|---|
| intro | 踏み込む → rush | レイナの右拳が動く瞬間、桜華の前脚を前進に合わせる |
| intro | かわす → evade | 拳がレンズを横切る。桜華の下降姿勢を同じ方向に合わせる |
| intro | 誘い込む → feint | 桜華の肩の引きから誘いの構えへつなぐ |
| rush | 肘で崩す → elbow | 伸びた拳を畳んで肘の軌道へ移す |
| rush | 下段を払う → sweep | レイナの高いガードから低い足元へカメラを落とす |
| rush | 引いて回避 → evade | 押し返された力を利用して後退、雨場面へ切り替える |
| evade | カウンター → counter | 空振り拳が通過した同じ画面方向で反撃へ |
| evade | 壁へ誘導 → wall | 相手の前傾を横へ流し、壁を画面右に出す |
| evade | 足を払う → sweep | 低い体勢を保ったままレイナの前脚へ移す |
| feint | 迎え撃つ → counter | 前進してきた相手の拳の内側へ切り返す |
| feint | 足元を狙う → sweep | 相手の重心が前脚に乗る瞬間を足払いの頭につなぐ |
| feint | 間合いを詰める → rush | フェイントで空いた間合いに踏み込む |
| elbow | 決着の一撃 → finish | 肘の衝撃による顔の寄り→共通フィニッシュ姿勢 |
| elbow | 投げに移る → throw | 肘を畳んだ腕から組み手へ |
| elbow | 距離を取る → breakaway | 身体を後方に回して安全に離す |
| sweep | 追撃の蹴り → finish | 足払いの戻し脚から回転蹴りへ |
| sweep | 立て直しを狩る → throw | 片膝のレイナの起き上がりを組み手へ |
| sweep | 間合いを切る → breakaway | 屈んだ姿勢から立ち上がり残心へ |
| counter | 一気に決める → finish | 拳の打撃エネルギーを上半身回転に残す |
| counter | 投げる → throw | 相手の崩れた肩を掴む動線へ |
| counter | 構えを戻す → breakaway | 拳を戻す途中から一歩下がる |
| wall | 壁を使う → finish | 壁を前景で隠して共通の決め技へ |
| wall | 投げ飛ばす → throw | 相手が壁から離れる動作で組み手へ |
| wall | 勝負を締める → breakaway | 壁際の相手を解放して離脱 |
| throw | 着地に追撃 → finish | 落下の一瞬のカメラ振りを接続頭へ |
| throw | 残心を決める → breakaway | 投げ終わりの強い立ち姿をそのまま残す |
| throw | 間合いを離す → breakaway | 投げ終わりから慎重に二歩後退 |
| stumble | 立て直す → counter | よろめきから前脚を固定し反撃 |
| stumble | 離脱する → breakaway | よろめきから重心を後ろへ引き直す |
| stumble | 捨て身の攻撃 → finish | 肩を突き出す動線から激しい決着へ |

選択ウィンドウ外・無入力: どの選択ノードでも `stumble` へ（ただし `stumble` で再度失敗すると `knockout`、HPゼロでも `knockout`）。失敗を受ける共通「崩れの挿入カット」が必要。

## 5. 4つの完成ルート（視聴体験サンプル）

1. **華麗な先制:** `intro → rush → elbow → finish`。桜花舞う対峙→突進→近距離の肘→大回転の決め。強攻撃をつないだ短い王道アクション。
2. **映画的な転換:** `intro → evade → wall → throw → finish`。桜→雨→ネオン→寺院→桜。画面を横切る腕・水滴・ライト・朱色の柱で舞台が変わる「動画であることの独自性」を最も強く見せるルート。
3. **静かな決着:** `intro → feint → sweep → breakaway`。演技で誘って足元を制し、追撃せず構えを解く。スコア至上ではなく美しい終幕が成立する。
4. **失敗から逆転:** `intro → stumble → counter → finish`。判断の失敗を一度見せてから、反撃で一本の映像として盛り返す。リテイクを使わずに逆転できる。

## 6. 制作物の単位・絵コンテ化の順番

### 映像アセットの単位
- **13本の主ショット**をひとまず字コンテの単位とする。ただし実際には各ノードの「入口の姿勢」が異なるため、これだけで全30分岐が自然につながるわけではない。
- **接続頭（ブリッジ）:** 初期は `前進`・`回避`・`反撃`・`組み手`・`決着` の5種の姿勢／遮蔽パターンで共通化。目立つ箇所は分岐専用ブリッジを増やす。
- **必須参照:** 桜華とレイナの全身・正面・横・背面・表情・衣装・手袋・靴、4背景の照明・位置・遠近の基準画。後続の絵コンテで確定する。
- **収録安全:** 映像の接触は殺陣として演じ、実際に打撃を入れない。合成、カメラ角度、リアクションで命中感を構成する。
- **MVP制作の優先順位:** `intro,rush,elbow,finish` → `evade,counter,stumble,knockout` → `feint,sweep,breakaway` → `wall,throw`。初回の試作は最初のルートの映像を自然につなぐことを最優先にする。

### 絵コンテへの展開
1. **キャラの基準画と衣装・動きの統一**（2人、各4面・ポーズ・表情）。
2. **各ノード3〜5コマ程度の絵コンテ**（入口、予兆、判断、終端）、合計およそ45〜60コマ。選択分岐は矢印で結ぶ。
3. **切替接続の絵コンテ**（全30エッジのうち映像のつながりが危険な箇所を優先）。
4. **アニマティック**で秒数、予兆の読める時間、選択タイミングを検証。
5. **実写風動画制作**→接続確認→ゲームに登録。

## 7. 現行実装との差分・制作前の必須修正候補

- **舞台名の不一致:** 現在の`graph.js`には場所が「桜の屋上」のまま画作りがRAIN/TEMPLE/NEONになるノード（`evade`, `feint`, `elbow`等）がある。字コンテでは編集上の転換として扱うが、映像制作前に画面上の地名・カット名を統一する。
- **映像尺と判断の忙しさ:** 現在2.1〜2.9秒のノードが中心。実写の予兆が読めない場合は3〜4秒台への拡張を検討し、動画・判定・UIを一体で調整する。
- **動作接続の欠落:** 現状はノードごとに単一動画を割り当てる構造。ブリッジ／入口バリエーション（元ノード・選択IDで選ぶ）を実装するまで、30本の分岐が自然につながる保証はない。
- **映像のトリミング:** いまの`object-fit:cover`ではiPhoneの実画面比によって手足が切れる。映像窓の縦横比・安全領域・表示方法を試験してから本編素材を大量生成する。
- **結果画面:** リプレイは現在ゲーム内再生。一本の映像ファイルとして保存する機能は未実装。
- **スローモーション:** 映画的な速度変化は絵コンテ上の演出指定であり、動画再生エンジンへの反映は次段階。

**本ドキュメントは字コンテのみ。画像・動画素材を生成／変更したものではない。最終映像制作は絵コンテとキャラ基準資料の確定後に行う。**
